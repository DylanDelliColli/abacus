## Observations

### High-level CLI surface

The release provides the normalized operations ABACUS needs without synthesizing terminal keystroke sequences:

- `agent start <name> --kind <kind> --pane <id>`
- `agent prompt <target> <text>` with optional bounded wait
- `agent wait`, `agent read`, and `agent send-keys`
- workspace/pane create, get/list, atomic `pane run`, bounded `pane read`, and `pane wait-output`
- `api snapshot` and a bundled versioned JSON schema

The v1 adapter should prefer this high-level CLI/JSON facade. Direct socket use remains a later optimization only if it supplies a measured benefit without widening the public runtime interface.

### Runtime namespace and isolation

A headless named session `abacus-spike` created an isolated workspace and pane. Atomic `pane run` delivered one harmless command; bounded `wait-output` and `read` observed it; `api snapshot` returned version/protocol, workspace/tab/pane handles, cwd, liveness observations, and terminal identity.

`HERDR_CONFIG_PATH` and `HERDR_SOCKET_PATH` did not relocate named-session state in this release. The disposable namespace lived under Herdr's standard user session root. The test installed no integrations and touched no other named/default session. It then stopped and deleted `abacus-spike`, and verified that exact directory was gone.

T3 therefore cannot claim that all Herdr state is redirected. It must instead use a collision-resistant `abacus-spike-<nonce>` named session, capture an exact pre/post namespace manifest, install no global integration/plugin, and stop/delete only that explicit namespace.

### Restart and handle fencing

Before server restart the pane ID was `w1:p1` and terminal ID was `term_6583b76c95f9c1`. After explicit stop/restart, the layout and pane ID restored as `w1:p1`, but the terminal ID became `term_6583b7b1055891`; the original process/output did not survive.

An opaque ABACUS runtime handle must therefore include provider session namespace, pane ID, and terminal/process generation identity. Pane ID alone is unsafe. A generation change reports stale/unknown and requires explicit re-association; it never silently attaches the old Attempt to a replacement shell. Native agent-session restoration must be verified separately and does not erase this fencing rule.

### Sandbox access

Inside the current workspace sandbox, direct access to Herdr's standard user socket returned `Operation not permitted`; the exact same high-level CLI call worked with explicitly approved host access. PTY creation similarly required host access. This remains a deployment/spike gate: an orchestrator must have an approved way to invoke the pinned Herdr facade, without moving runtime control into Scribe or weakening domain boundaries.

## Cleanup

The live `abacus-spike` server was stopped and its named session deleted through Herdr. No Herdr integration, plugin, default session, Claude/Codex configuration, shell configuration, or source repository was modified. The downloaded binary remains only in `/tmp/abacus-herdr-spike.tBWefh`.
